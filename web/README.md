# parcelpulse-web

Web dashboard for ParcelPulse, a package tracking and delivery notification
platform. Built with Next.js (App Router), React and TypeScript.

This directory is the former `parcelpulse-web` repository, imported with its
commit history into the ParcelPulse engineering repository. Run the commands
below from `web/`.

Users look up a parcel by tracking number, add new shipments, follow each
shipment's timeline and choose which email notifications they get. All data
comes from `parcelpulse-api`; this application stores nothing.

See [docs/frontend.md](docs/frontend.md) for the structure, data flow and
testing approach. System-level documentation lives in [`docs/`](../docs/) at
the repository root.

## Requirements

- Node.js 22 or newer (CI and the Docker image use Node 24)
- A running `parcelpulse-api`

## Setup

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

The app is served on <http://localhost:3000>. The quickest way to get an API
to talk to is the stack in `infra/` (`docker compose up --build`),
which also serves this dashboard from its Docker image on the same port; stop
that `web` container, or run `npm run dev -- --port 3001`, to develop against
the stack.

## Configuration

Read on the server at request time; nothing is exposed to the browser.

| Variable             | Default                 | Purpose                                              |
| -------------------- | ----------------------- | ---------------------------------------------------- |
| `API_BASE_URL`       | `http://localhost:8000` | Where the Next.js server reaches `parcelpulse-api`   |
| `ENABLE_DEV_TOOLS`   | unset (off)             | `true` enables `/dev`, the carrier simulator controls |
| `SIMULATOR_BASE_URL` | `http://localhost:8100` | Carrier simulator, used only by `/dev`               |
| `MAIL_SINK_URL`      | `http://localhost:8025` | Link to the local mail sink shown on `/dev`          |

## Checks

```powershell
npm run lint        # ESLint
npm run typecheck   # generates route types, then tsc --noEmit
npm test            # Vitest
npm run build       # production build
```

CI (`.github/workflows/web-ci.yml` at the repository root) runs these as
separate jobs, with one test job per area, plus the Docker image build.

## Docker

```powershell
docker build -t parcelpulse-web .
docker run --rm -p 3000:3000 -e API_BASE_URL=http://host.docker.internal:8000 parcelpulse-web
```

The image runs the Next.js standalone server as a non-root user.
`GET /api/health` is its liveness check; `GET /api/ready` also verifies that
the API is reachable and ready.

## Branches

`main` is always releasable. Work happens on short-lived branches named
`feature/*`, `fix/*`, `docs/*` or `release/*` and is merged through pull
requests. See [../docs/team-workflow.md](../docs/team-workflow.md).

## Note on `AGENTS.md`

`AGENTS.md` (and `CLAUDE.md`, which includes it) is generated by the Next.js
tooling and re-created by `next dev`. It tells coding agents to consult the
version-matched documentation in `node_modules/next/dist/docs/`, because this
Next.js major version differs from older ones in several conventions.
